# Interface Internals

> Go interfaces are one of its most powerful features -- implicit satisfaction, no inheritance. Under the hood, they're a pair of pointers with smart caching.

## Empty Interface (eface)

When you use `interface{}` (or `any` in Go 1.18+), the runtime represents it as an `eface` -- the simplest interface struct:

```go
type eface struct {
    _type *_type          // pointer to type descriptor
    data  unsafe.Pointer  // pointer to actual data
}
```

- `unsafe.Sizeof(interface{}{})` = **16 bytes** (2 x 8 bytes on 64-bit) -- always, regardless of what's stored inside.
- Every `interface{}` stores two things: **what type** the value is + **where the data** lives.
- `_type` is the runtime's universal type descriptor:

```go
type _type struct {
    size       uintptr
    ptrdata    uintptr  // size of memory prefix holding pointers
    hash       uint32   // for fast type comparison and type switches
    tflag      tflag
    align      uint8
    fieldAlign uint8
    kind       uint8    // Bool, Int, Struct, Ptr, Interface, etc.
    equal      func(unsafe.Pointer, unsafe.Pointer) bool
    gcdata     *byte
    str        nameOff
    ptrToThis  typeOff
}
```

The `_type` struct is generated by the compiler for every concrete type in your program. It lives in the read-only segment of the binary.

```go
var x interface{} = 42
// eface { _type: *_type(int), data: pointer to 42 }

var y interface{} = "hello"
// eface { _type: *_type(string), data: pointer to StringHeader{"hello"} }
```

## Non-Empty Interface (iface)

For interfaces that declare methods (e.g., `io.Reader`, `fmt.Stringer`), Go uses a different struct:

```go
type iface struct {
    tab  *itab           // pointer to itab (type + method table)
    data unsafe.Pointer  // pointer to actual data
}
```

- Also **16 bytes** on 64-bit, same as `eface`.
- The key difference: instead of a bare `_type`, it stores a pointer to an `itab` -- a richer structure that includes the method dispatch table.
- `data` works identically to `eface.data`.

```go
var r io.Reader = os.Stdin
// iface { tab: *itab(io.Reader, *os.File), data: pointer to os.Stdin }
```

## The itab Structure

The `itab` is the heart of Go's interface dispatch mechanism:

```go
type itab struct {
    inter *interfacetype  // static interface type (e.g., io.Reader)
    _type *_type          // dynamic concrete type (e.g., *os.File)
    hash  uint32          // copy of _type.hash (for fast type switches)
    _     [4]byte         // padding
    fun   [1]uintptr      // variable-sized method table
}
```

### How `fun` works

- `fun` is declared as `[1]uintptr` but is actually **variable-sized** -- one entry per method in the interface.
- For `io.Reader` (1 method), `fun` has 1 entry: `[Read]`.
- For `io.ReadWriteCloser` (3 methods), `fun` has 3 entries: `[Read, Write, Close]`.
- Methods are sorted alphabetically, matching the interface's method order.

```
itab for (io.ReadWriteCloser, *os.File):
+------------------+
| inter: ---------> io.ReadWriteCloser type info
| _type: ---------> *os.File type info
| hash:  0x1a2b3c  (copy of *os.File hash)
| fun[0]: --------> (*os.File).Close
| fun[1]: --------> (*os.File).Read
| fun[2]: --------> (*os.File).Write
+------------------+
```

### Global itab Cache

- itab is computed **once** per (interface, concrete type) pair.
- Stored in a **global hash table** (`itabTable`) keyed by `(inter, _type)`.
- First lookup: O(n*m) where n = interface methods, m = concrete type methods (sorted, so actually O(n+m)).
- Subsequent lookups: **O(1)** -- directly from the hash table.
- The hash table grows dynamically and is lock-free for reads.

```go
// Pseudocode for itab lookup
func getitab(inter *interfacetype, typ *_type) *itab {
    // 1. Check global hash table (fast path)
    if tab := itabTable.find(inter, typ); tab != nil {
        return tab
    }
    // 2. Compute new itab (slow path)
    tab := newItab(inter, typ)
    // 3. Cache it
    itabTable.add(tab)
    return tab
}
```

## Type Assertions

Type assertions extract the concrete value from an interface. Their cost depends on what you're asserting to.

### Asserting to a concrete type

```go
var i interface{} = 42

v, ok := i.(int) // checks: i._type == *_type(int)
// Fast: just compare _type pointers, then return data
```

- Compiles to a pointer comparison on `_type`.
- If match: copies data out. If no match: `ok = false`, `v = zero value`.
- Cost: **O(1)** -- a single pointer comparison.

### Asserting to an interface

```go
var i interface{} = os.Stdout

w, ok := i.(io.Writer) // needs to find itab for (io.Writer, *os.File)
```

- Requires an **itab lookup** -- must verify the concrete type has all methods of the target interface.
- First time: builds and caches the itab. Subsequent times: O(1) cache hit.

### Type switch

```go
switch v := i.(type) {
case int:      // compares _type.hash, then _type pointer
case string:   // compares _type.hash, then _type pointer
case io.Reader: // itab lookup
}
```

- Uses `_type.hash` for **fast initial comparison** (avoids string comparison of type names).
- On hash match, verifies with pointer comparison to handle hash collisions.
- Interface cases still require itab lookup.

## Interface Satisfaction

Go interfaces are **implicitly satisfied** -- there is no `implements` keyword:

```go
type Reader interface {
    Read(p []byte) (n int, err error)
}

type MyFile struct{}

func (f *MyFile) Read(p []byte) (int, error) {
    return 0, nil
}

// *MyFile automatically satisfies io.Reader -- no declaration needed
var r io.Reader = &MyFile{}
```

### Compile-time vs runtime checking

- **Compile time**: When the compiler can see both the interface and concrete type, it verifies satisfaction and reports errors immediately.
- **Runtime**: When types are determined dynamically (reflection, type assertions), the check happens via itab computation.

### Method sets: `T` vs `*T`

This is a critical distinction:

```go
type Dog struct{}

func (d Dog) Speak() string  { return "Woof" }  // value receiver
func (d *Dog) Fetch()        { /* ... */ }        // pointer receiver

type Speaker interface { Speak() string }
type Fetcher interface { Fetch() }

var s Speaker = Dog{}   // OK: Dog has Speak() with value receiver
var f Fetcher = Dog{}   // COMPILE ERROR: Dog does not have Fetch()
var f Fetcher = &Dog{}  // OK: *Dog has both Speak() and Fetch()
```

| Receiver Type | Method Set |
|---|---|
| Value `T` | Only methods with value receiver `(t T)` |
| Pointer `*T` | Methods with value receiver `(t T)` AND pointer receiver `(t *T)` |

**Why?** A value might not be addressable (e.g., map values, return values), so you can't always get a `*T` from a `T`. But you can always get a `T` from a `*T` by dereferencing.

```go
// This is the compile-time assertion idiom:
var _ io.Reader = (*MyFile)(nil)  // proves *MyFile satisfies io.Reader
```

## Nil Interfaces vs Nil Data

This is Go's **most common interface gotcha**:

```go
var i interface{} = nil     // i == nil  (both _type and data are nil)
var p *int = nil
var i2 interface{} = p      // i2 != nil! (_type is *int, data is nil)
```

Why? An interface is `nil` only when **both** `_type` and `data` are nil. Once you assign a typed nil pointer, the interface knows the type -- it's no longer a nil interface.

```
i (nil interface):          i2 (non-nil interface with nil data):
+--------+--------+        +--------+--------+
| _type: nil      |        | _type: *int     |
| data:  nil      |        | data:  nil      |
+--------+--------+        +--------+--------+
  i == nil: true              i2 == nil: false
```

### The Classic Mistake

```go
func getError() error {
    var err *MyError = nil  // typed nil
    return err              // wraps in interface: iface{tab: *itab, data: nil}
}

if getError() != nil {
    // This ALWAYS executes! The interface is not nil.
    fmt.Println("got error") // surprise!
}
```

### The Fix

```go
func getError() error {
    var err *MyError = nil
    if err == nil {
        return nil  // return untyped nil -- the interface will be truly nil
    }
    return err
}
```

## Boxing / Allocation

When a value is stored in an interface, it may need to be **boxed** (allocated on the heap):

### Small values: direct storage

Values that fit in a pointer (8 bytes on 64-bit) are stored **directly** in the `data` field -- no heap allocation:

```go
var i interface{} = 42       // int fits in 8 bytes -- stored directly in data
var j interface{} = true     // bool fits in 8 bytes -- stored directly
var k interface{} = uintptr(0) // pointer-sized -- stored directly
```

### Large values: heap allocation

Values larger than a pointer require a **heap allocation**:

```go
var i interface{} = [100]int{} // 800 bytes -- allocated on heap, data points to it
var j interface{} = BigStruct{} // too large for data field -- heap allocated
```

### Compiler optimizations

The Go compiler applies several optimizations to reduce interface overhead:

**Devirtualization**: When the compiler can prove the concrete type at compile time, it replaces interface method calls with direct calls:

```go
var w io.Writer = os.Stdout
w.Write([]byte("hello"))
// If the compiler can prove w is always *os.File,
// it replaces iface.tab.fun[0](data, ...) with (*os.File).Write(stdout, ...)
```

**Escape analysis**: If an interface value doesn't escape the current function, the boxing allocation may happen on the stack instead of the heap:

```go
func foo() {
    var i interface{} = 42 // may stay on stack if i doesn't escape
    fmt.Println(i)          // but Println causes i to escape to heap
}
```

**Static itab**: For interface conversions visible at compile time, the compiler generates the itab statically in the binary instead of computing it at runtime.

## Performance Notes

| Operation | Cost | Allocates? |
|---|---|---|
| Interface method call | Indirect call (pointer chase through itab) | No |
| Type assertion to concrete | O(1) pointer comparison | No |
| Type assertion to interface | O(1) itab cache hit (after first) | No |
| Boxing small value (≤ 8 bytes) | O(1) | No |
| Boxing large value (> 8 bytes) | O(n) copy | Yes (heap) |
| First itab computation | O(n+m) method matching | Yes (itab) |

### When to avoid interfaces

```go
// HOT PATH: avoid interface overhead
// Instead of:
func process(r io.Reader) { ... }

// Use the concrete type directly:
func process(r *bytes.Buffer) { ... }
```

The overhead is small (1-3ns per call for the indirection), but in tight loops processing millions of items, it adds up. Profile before optimizing.
